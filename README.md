# Project V

**Do explanations of manipulation policies survive dynamics shift?** Closed-loop faithfulness of
state attributions and attribution-shift failure prediction for SAC+HER policies on
Gymnasium-Robotics `FetchReach` / `FetchPush` (MuJoCo).

All transfer results here are on **held-out dynamics in simulation (sim-to-sim)**. Nothing in
this repository tests transfer to a real robot.

| ID | Question | Code |
|---|---|---|
| C1 | Are attribution methods faithful in closed loop, not only open loop? Ground truth from an analytic Cartesian PD controller and a planted-shortcut policy | `projectv/xai/faithfulness.py` |
| C2 | GWIE-C, a guided iterative-erasure attribution for continuous Gaussian policies over feature groups, adapted from GWIE (DePlag) | `projectv/xai/gwie_c.py` |
| C3 | Does a shift in attributions (Attribution-Shift Monitor, ASM) predict failure on held-out dynamics earlier or better than 5 baselines? | `projectv/monitor/` |
| C4 | How does dynamics domain randomization (DR) change feature and temporal reliance, and do DR+History policies encode dynamics parameters linearly? | `projectv/analysis/` |

Scope, hypotheses and acceptance criteria: [`mvp.md`](mvp.md). Decisions and deviations:
[`CHANGELOG.md`](CHANGELOG.md). Draft report: [`report/report.md`](report/report.md).

## Setup

Python 3.10 or 3.11 matches the Kaggle image (local development also ran on 3.13). Torch and
numpy come from the Kaggle/Colab image; install CPU torch locally.

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                    # or requirements.lock for pinned versions
pip install -e . --no-deps
pytest -q tests/test_envs.py tests/test_wrappers.py
```

Rendering (GIFs) uses MuJoCo's renderer. On Linux set `MUJOCO_GL=egl` on GPU sessions or
`MUJOCO_GL=osmesa` on CPU sessions (needs `libosmesa6`); `scripts/make_gifs.py` defaults to `egl`
if the variable is unset. `python scripts/make_gifs.py --check-render out.gif` renders a few frames
of the analytic controller to check the backend.

Only free resources are used: Kaggle Notebooks, Colab (free), GitHub, Hugging Face Hub (free),
optional W&B free tier (`--no-wandb` always works).

## Reproduce

The commands below are the project's entry points (CLAUDE.md §5). Every entry point takes
`--seed`, `--out`, `--no-wandb` and writes a `run_meta.json` (git SHA, config hash, versions,
wall-clock). Progress on each step is tracked in [`docs/tasks.md`](docs/tasks.md).

```bash
# sanity
pytest -q tests/test_envs.py tests/test_wrappers.py

# pilot (measures steps/sec, ~50k steps)
python -m projectv.train.train --exp configs/exp/push_dr.yaml --seed 0 --total-steps 50000 --tag pilot

# full training run (resumable)
python -m projectv.train.train --exp configs/exp/push_dr.yaml --seed 1 --resume auto

# calibrate + freeze held-out grid (Day 1, once)
python scripts/calibrate_heldout.py --policy results/ckpt/push_dr_s0_pilot.zip

# held-out sweep with per-step logging
python -m projectv.eval.heldout_sweep --exp configs/exp/push_dr.yaml --seeds 0 1 2 --episodes 100

# analyses
python -m projectv.xai.faithfulness --task reach_controller
python -m projectv.xai.faithfulness --task push --exp push_dr
python -m projectv.monitor.asm --exp push_dr
python -m projectv.analysis.reliance --task push
python -m projectv.analysis.probes --task push

# outputs
python scripts/make_tables.py && python scripts/make_figs.py && python scripts/make_gifs.py
```

The analytic-controller C1 results shown below come from
`python -m projectv.xai.faithfulness --task reach_controller` and `--task push_controller`
(no training needed).

## Cloud workflow (free tier)

**Kaggle (training and sweeps).** `notebooks/kaggle_train.ipynb` clones the repo, installs
`requirements.lock`, and runs several (experiment, seed) runs as parallel subprocesses
(`torch.set_num_threads(1)` each) into `/kaggle/working/results`.
`scripts/make_kaggle_kernels.py` generates one kernel per session from that notebook. Run each
kernel headless with **Save Version → Save & Run All (commit)**. Sessions can die, so checkpoints
are written every 50k steps and the replay buffer every 200k. To resume, attach the previous
version's output as an input dataset and pass `--resume auto`. Secrets (W&B key, GitHub token)
come from Kaggle Secrets and are never stored in code. CPU sessions are the default.

**Colab (analysis).** Notebooks only call `projectv` modules and scripts. Every analysis writes
partial results incrementally and skips finished units on a rerun, so a disconnect loses little.

**Artifacts.** Final checkpoints go to a free Hugging Face Hub repo. Small tables and figures live
in `results/`.

## Implementation notes

- **GWIE-C** is adapted from GWIE (DePlag). Every deviation from the original is listed in
  [`docs/gwie_original.md`](docs/gwie_original.md). The original is a counterfactual-set search
  over words. GWIE-C keeps its guided-erasure loop (IG on the current erased state, magnitude
  pivot) but erases feature groups and gives every group a marginal KL gain. A direct port
  (`gwie_orig_port`) is reported alongside it.
- **"Actuator gain" DR** is a multiplier on the mocap end-effector step size, applied after the
  env's action clip. Fetch uses mocap control, so arm joint dynamics barely matter, and this is
  not an actuator-gain randomization in the usual sense.
- **Friction DR.** MuJoCo combines contact friction as the element-wise maximum of the two geoms.
  Scaling only the object geom would make low-friction cells no-ops against the table. The object
  and table geoms therefore both receive the product of the object- and table-friction
  multipliers, so the object–table contact uses that product. A side effect is that gripper
  contacts get `max(1, product)`. Under nominal multipliers the physics is identical to the
  stock env.
- **Mass DR** scales the object's mass and inertia. **Observation noise** is also applied to the
  duplicated `achieved_goal` slice, so the policy cannot read a clean copy.
- Attributions are computed in raw observation units over semantic feature groups.
  `achieved_goal` is grouped with `obj_pos`, and the redundant cluster
  `{ee_pos, obj_pos, obj_rel}` is also erased jointly.

## Limitations

- **Simulation only.** Held-out dynamics are sim-to-sim: different friction, mass, mocap step
  size, observation noise and latency in the same simulator. Nothing here measures sim-to-real
  transfer.
- **n = 3 training seeds** per condition. CIs are wide, and per-seed values should be read
  alongside the means.
- One robot (Fetch, mocap control), two tasks and one algorithm family (SAC+HER, with TQC as the
  documented fallback). Results may not carry over to torque-controlled arms or other algorithms.
- The analytic-controller ground truth is linear. It validates implementations but is the easiest
  case for gradient methods.
- The held-out grid was calibrated on one pilot DR policy to give 20–80% success, then frozen.
  Cells that are hard for that policy are not a neutral sample of all possible shifts.
- GWIE-C's lineage claim covers the mechanism only. The original paper's monotonicity and
  guaranteed-convergence statements were not reproduced (see `docs/gwie_original.md`), and no
  such property is claimed for GWIE-C.
